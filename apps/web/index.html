A deliberate lifecycle

Keep what helps. Correct what changes. Forget what should go.

  1. 01

    Remember

    Capture a memory with category, provenance, confidence, and a reason—when your consent permits it.

  2. 02

    Retrieve

    Return relevant context as untrusted data, never as system instructions.

  3. 03

    Correct

    Review provenance and create a new version instead of silently overwriting history.

  4. 04

    Forget

    Preview the impact, confirm the destructive action, and receive an auditable result.

Security, stated carefully

Cloud v1 is designed for server-side retrieval.

It is not end-to-end encrypted or zero knowledge. The design calls for encrypted transport and storage controls, tenant isolation, scoped access, and auditable deletion—but those claims remain gated until staging evidence exists.

Questions worth answering

FAQ

Is UMCP conversation history?

No. It is a structured memory layer with provenance, versions, scopes, and a deliberate forget operation.

Is it end-to-end encrypted?

No. Cloud v1 is designed for server-side retrieval. We will only publish encryption claims after their implementation gates and staging evidence pass.

Does MCP compatibility mean every client works?

No. A surface is supported only after an authenticated write → search → update → forget report. Generic protocol compatibility is not a test result.

Can I self-host it today?

The Community Alpha path is local/self-hosted. Cloud identity and remote integrations remain implementation-ready work awaiting Terra's server adapters.
